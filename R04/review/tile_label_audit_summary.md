# R03 학습 타일·라벨 독립 검토

CPU에서 원본 XML 47개, 타일 425개의 교차 기하, 실제 YOLO 라벨 425개를 다시 계산했다. 학습·추론·GPU·원본 수정·원격 변경은 하지 않았다. 아래 수치는 R03 정적 데이터의 사실이며 성능 저하의 원인이 확정된 것은 아니다.

## 확인된 수치

| 종류 | 학습 원본 객체 | 타일 노출 | 반복 배수 | 면적 50% 미만 조각 | 전체 bbox가 포함된 타일 없음 |
|---|---:|---:|---:|---:|---:|
| resistor | 1,390 | 2,515 | 1.809 | 186 (7.40%) | 0 |
| capacitor | 1,570 | 2,898 | 1.846 | 232 (8.01%) | 0 |
| ic | 213 | 523 | 2.455 | 162 (30.98%) | 23 |
| connector | 311 | 797 | 2.563 | 265 (33.25%) | 65 |

총 3,484개 원본 객체가 6,733회 노출되고 그중 1,434회가 잘린 bbox이다. Claude의 IC 162/523, 커넥터 265/797, 전체 포함 타일이 없는 IC 23/213·커넥터 65/311은 모두 재현된다. 50% 기준은 bbox 면적이며 실제 부품 silhouette 가시 면적은 아니다.

양의 정수 교차 영역이면 1px 조각도 정답으로 쓴다. 조각 제거만 하면 해당 영역이 음성 배경이 되는 문제도 생기므로 단순 삭제가 곧 개선이라고 볼 수 없다. 전체가 보이는 타일 추가와 다중 스케일 등의 효과는 같은 예산의 A/B로 확인해야 한다.

## 보드별 노출의 의미

- ML365: 라벨 1,692회 (25.13%), 타일 40/425 (9.41%).
- Arty: 라벨 1,014회 (15.06%), 타일 47/425 (11.06%).
- XLVDSproSupply: 라벨 755회 (11.21%), 타일 60/425 (14.12%).

상위 세 보드의 라벨 노출은 3,461/6,733 = 51.40%이다. 다만 이는 학습 이미지나 gradient의 51%를 차지한다는 뜻은 아니다. 균일 타일 샘플링 기준 ML365는 타일의 9.41%이며, 실제 gradient 비중은 할당과 loss 정규화에도 좌우된다.

## 제외 객체와 ignore 수정 필요

학습 원본에서 pins 169, unknown 169, LED 107, jumper 52, transistor 47, switch 33이 제외된다는 수치가 원본 XML과 일치한다. 전체 유형별 수는 JSON에 기록했다.

검증된 비대상 유형을 배경으로 학습하는 것은 4종 검출 과제에서 정상적인 선택일 수 있다. 다른 부품을 목표 클래스로 예측하는 오류는 억제할 필요가 있다. 반면 unknown 안에 목표 부품이 섞여 있거나 pins/connector 등의 정답 정의가 겹치면 별도 검수가 필요하다. 이 두 경우를 하나로 묶어 모든 비대상을 ignore 처리하는 것은 권하지 않는다.

**회색으로 채우는 것은 현재 학습 코드에서 진짜 ignore가 아니다.** 설치된 Ultralytics의 detection criterion은 cls·bbox만 읽고 모든 anchor×class BCE를 합산한다. 회색 영역에서도 negative classification loss는 남는다. 시각적 삭제 실험이라고 기록해야 하며 adjacent positive 가림과 경계 artifact도 확인해야 한다.

실제 ignore를 적용하려면 ignore 영역 metadata, augmentation에 따른 좌표 변환, positive 우선순위, 음성 anchor loss 제외가 필요하다. 평가 ignore는 별도 규칙으로 구현해야 한다. loss.py의 semantic ignore_index=255 코드를 detection loss에도 적용되는 것으로 해석하면 안 된다.

other_component는 별도 5종 실험이다. 기존 4종 성능과 비교 규칙을 고정해야 하며, text·pads·unknown을 모두 전문가가 지정한 하나의 부품 종류라고 간주할 수 없다.

## 검증 범위

원본 XML 해시, 저장한 교차 비율, 실제 라벨 좌표, 원본 객체의 타일 누락 여부를 확인했다. 보호 대상 코드·JSON·XML·YOLO 라벨 파일의 실행 전후 SHA-256이 모두 같다. 자세한 파일별 해시와 재계산 수치는 tile_label_audit.json에 있다. D455 실물 성능 및 변경안의 정확도 효과는 검증하지 않았다.
