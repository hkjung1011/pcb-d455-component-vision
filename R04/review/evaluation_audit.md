## R04에 적용할 평가 규칙

1. 이미 진단에 사용한 R03 일반/Pi 시험 자료는 앞으로 **개선용 holdout**이다. 원래 membership과 source GT는 보존하되 새 최종 시험처럼 부르지 않는다. 실제 새 D455 시험셋은 아직 없다.
2. 기존 train+val 34장만으로 보드 그룹을 유지하면서 클래스·크기 coverage를 개선한 split을 고정한다. 후보 모델 예측이나 R03 시험 성능으로 split을 고르지 않는다. 새 split의 기준/개선 두 실험은 **같은 공식 pretrained SHA**에서 시작한다. R03 학습 가중치는 새 val 그룹 일부를 본 적 있어 새 split의 공정한 초기화로 쓰면 안 된다.
3. 각 arm 20에폭 이내, 동일한 직접 optimizer 호출 예산을 사전 지정한다. 타일·다중배율·oversampling이 바뀌면 같은 에폭은 같은 예산이 아니다. `nbs=8`을 유지해도 batch 변경으로 warmup 호출 수가 바뀐다. 직접 post-step hook, 파라미터 min/max, EMA updates, 배치/노출/시간을 분리 기록한다.
4. 2에폭 간격과 마지막 checkpoint를 실제 배포 입력 방식으로 native val 평가한다. Ultralytics `save_period` 파일명은 0부터 시작하는 내부 epoch 기준이므로 완료한 에폭 번호를 별도 기록한다. AP300을 1차, AP100을 호환 지표로 사전 지정하고 threshold·체크포인트 SHA를 고정한 뒤 holdout을 실행한다.
5. 비교는 같은 분할·같은 초기화·같은 직접 호출 예산으로 한다. 여러 증강과 loss 처리를 동시에 바꾸면 ‘개선 묶음’ 효과이며 각 요소의 원인 효과라고 해석하지 않는다.
6. 확실한 비대상 부품을 target4의 negative로 두는 것은 맞다. **unknown에는 목표 클래스가 섞일 수 있는 불완전 라벨 문제**가 남는다. 회색으로 덮는 것은 영상 masking이지 loss나 COCO에서 무시하는 기능이 아니다. ignore는 실제 적용 코드와 positive 우선 규칙을 검증해야 한다.
7. 원본 GT와 변경한 라벨의 지표는 구분한다. footprint 등 source GT 해석 검토가 있더라도 R03 원본 점수를 소급 변경하지 않는다. 단일 고정 threshold와 val에서 정한 클래스별 threshold를 비교한다면 선택 규칙도 사전에 고정한다.

이 감사는 데이터·학습·평가 기록의 해석을 검증했다. D455 실제 화질, 부품 윤곽 라벨, 실사용 성능을 검증한 결과는 아니다.
