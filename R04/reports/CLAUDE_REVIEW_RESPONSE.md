# Claude R03 검토에 대한 확인 결과와 R04 반영

작성일: 2026-09-28. 이 문서는 두 번째 Claude 검토를 원본 자료·저장 예측·코드와 대조한 **검토 반영 기록**이다. R04의 새 학습 성능 결과가 확정되기 전에 작성했다. 아래 R03 지표와 R04 데이터 준비 수치를 구분하며, R04 정확도 개선이나 실제 D455 성능을 예측하지 않는다.

검토의 중심인 **타일의 심한 잘림, 검증 자료의 크기 분포, 배포 조건에 맞춘 체크포인트 선택**은 개선할 근거가 있다. 반면 ‘회색으로 덮으면 ignore’, ‘확실한 비대상도 모두 제외’, ‘축소 결과가 D455 성능 하한’은 그대로 적용하지 않았다. 현재 목표는 저항·커패시터·IC·커넥터의 4종 bbox 검출이며, 향후 실제 instance mask는 별도 정답과 평가로 진행한다.

## 1. 주장별 확인과 적용

‘확인’은 수치·코드·사진으로 재현한 사실, ‘부분 수용’은 사실과 해석을 나눠 적용한 항목, ‘정정’은 그대로 쓰면 오해가 생기는 항목이다. 원인을 확정하려면 같은 조건의 실험 결과가 필요하다.

| 검토 항목 | 판단 | 확인한 사실과 R04 처리 |
|---|---|---|
| IC·커넥터에 면적 50% 미만 조각이 많음 | 확인 | R03의 IC 162/523회(30.98%), 커넥터 265/797회(33.25%)를 재현했다. 50%는 **bbox 교차 면적**이지 실제 silhouette 면적이 아니다. R04 개선 팔에서는 심하게 잘린 조각을 ignore 영역으로 기록한다. |
| 전체 형태를 한 번도 보지 못한 큰 부품 | 확인 | R03에서 IC 23/213개, 커넥터 65/311개가 어느 타일에도 완전히 들어가지 않았다. R04 개선 팔은 2048 문맥 crop과 객체 중심 crop을 추가했고, 새 train의 3,307개 객체 모두가 적어도 한 view에 완전히 들어간다. 정확도 효과는 평가 전이다. |
| 모든 비대상·unknown을 배경으로 두면 안 됨 | 부분 수용 | unknown에는 target4가 섞일 수 있다. 그러나 확인된 LED·트랜지스터 등은 4종 과제의 정상적인 비대상 예시가 될 수 있다. R04에서는 **unknown만 ignore**하고 확인된 비대상은 배경으로 유지한다. pins/connector 등의 정의가 겹치는 사례는 별도 검수 대상으로 남긴다. |
| 회색으로 채워 ignore 처리 | 정정 | 회색 영상에서도 음성 classification loss는 남는다. R04는 원본 픽셀을 덮지 않고 좌표 sidecar와 실제 음성 anchor loss 제외를 구현했다. 확정된 positive가 겹치면 positive를 우선한다. CPU 11개 검사와 batch 4의 GPU forward/backward 점검은 통과했지만 이는 AP 개선 증거가 아니다. |
| 검증셋에 작은 부품이 적음 | 확인 | R03의 원본 짧은 변 8–16 px는 val 24/875(2.74%), 일반 test 446/1,348(33.09%), Pi 77/189(40.74%)다. R04는 기존 train+val의 23그룹만으로 새 val 6그룹을 정했다. 새 val은 98/1,052(9.32%)다. test 비율에 맞춰 분할하지 않았으며, D455를 대표한다고 주장하지 않는다. |
| best.pt가 배포와 다른 입력으로 선택됨 | 부분 수용 | 학습 중 best는 whole-image 1024 val에서 고른 것이 맞다. R03에서도 이후 best/last×whole/tile을 원본 val로 재비교했으므로 배포 조건을 전혀 평가하지 않은 것은 아니다. R04는 2에폭마다 저장한 후보와 native/dual 추론을 원본 val에서 비교하도록 정했다. |
| s best는 18에폭 | 확인, 근거 명시 | stripped checkpoint의 epoch는 -1이다. best의 train_metrics와 CSV가 18에폭에서 유일하게 일치해 재구성했다. n은 같은 방식으로 17에폭이다. 직접 저장된 epoch 값과 재구성값을 혼동하지 않는다. |
| 그림05에 학습 val와 최종 평가 차이가 없음 | 부분 정정 | 기존 그림 제작 코드의 footer는 두 조건의 차이를 이미 설명했다. ‘전체 영상 1024 축소’와 선택 에폭을 더 명확히 적는 것은 타당하다. |
| s 3에폭 cls loss 급등은 불안정 징후 | 확인, 원인 미확정 | val cls loss 1,634.9165와 dfl loss 56.24868은 기록에 있다. batch·학습률이 원인이라는 결론은 실험으로 확인하지 않았다. R04는 FP32를 유지하며 nonfinite 검사와 실제 갱신 기록을 강화한다. |
| batch 8이면 메모리와 step가 충분함 | 부분 수용 | 기존 peak만으로 batch 8 성공을 보장할 수 없다. R04는 batch 4를 사용한다. 실제 1024 FP32 batch 4 forward/backward 점검에서 peak allocated 약 4.38 GiB, reserved 약 5.40 GiB였다. nbs=8이어도 warmup 때문에 batch 변경 전후 step가 자동으로 같아지는 것은 아니다. |
| optimizer 1,164/2,605/1,432 표기 수정 | 확인 | 기존 수치는 파라미터별 AdamW state.step의 **최솟값**이다. Claude의 1,165/2,615/1,477은 최댓값 및 trainer 규칙으로 재구성한 호출 수와 일치하지만 당시 직접 hook 측정값은 아니다. R04는 optimizer post-step hook으로 실제 호출을 센다. |
| 밀집 영상의 AP@100은 한계가 있음 | 확인 | 사진·클래스별 상위 100개 제한의 영향을 받는다. R03의 AP100/AP300 계산은 재집계와 일치했다. 역사 지표를 바꾸지 않고 R04는 **AP50–95 maxDets=300을 주 지표**, maxDets=100을 호환 지표로 사전 지정했다. |
| s가 n보다 낫다는 일반 결론 | 정정 | s는 R03 val에서 선택한 기본 모델이다. Pi 한 그룹으로 일반적 우위를 입증할 수 없다. n/s precision은 고정 confidence 0.60/0.35라는 서로 다른 운용점의 영향도 받는다. |
| 보드 검출의 출처별 차이를 드러내야 함 | 수용 | 저장된 출처별 결과에서 IoTKITs 490장의 bbox AP는 검출 모델 64.15%이고, 합산 점수와 구별해야 한다. 다만 IoTKITs 점수 하나를 실사용 일반화의 정답으로 간주할 수도 없다. 인터넷 출처·물리 보드 독립성이 미확인이다. R04 이번 실험은 부품 모델에 한정한다. |
| ML365와 상위 3보드 노출 편중 | 확인, 의미 보정 | R03 라벨 반복 노출의 ML365 비중 25.13%, 상위 3개 51.40%를 확인했다. 이는 이미지나 gradient 비중이 아니다. R04 양쪽 팔에 같은 그룹 균형 샘플링을 적용하며 클래스별 반복 수와 실제 추출 수를 별도로 기록한다. |
| 커넥터 2개가 미실장 패드임 | 시각 확인, GT 오류 확정 안 함 | Top RUN과 Bottom unknown annotation이 열린 2핀 패드를 둘러싼다. 같은 위치의 양면일 가능성도 있으므로 독립 부품 2개라고 세지 않는다. 원본 XML이 connector로 지정했기 때문에 기존 시험 GT에서 일괄 삭제하지 않는다. 새 실장 부품 계약에서는 DNP 속성과 별도 정답 버전을 사용한다. |
| 실장 기준으로 커넥터 재현율 상한이 10/12 | 정정 | 기존 source 정의라면 패드까지 예측할 수 있어 모델의 수학적 상한은 아니다. 실장 부품만 평가하는 새 정답은 새 분모를 가져야 한다. 원본 점수는 보존한다. |
| J9 microSD를 IC 0.91로 오분류 | 확인 | 저장된 IC score 0.913919, connector GT와 IoU 0.926268이다. 점수 부족뿐 아니라 고신뢰 클래스 혼동 사례도 존재한다. |
| 커넥터 7/12·IC 8/13에서 낮은 점수의 같은 클래스 상자 존재 | 진단 취지 확인, 수치 정정 | 후속 CPU 감사에서 고정 confidence의 FN에 대해 같은 클래스·IoU≥0.5 저장 후보를 찾으면 **커넥터 8/12, IC 9/13**이다. 후보 중복은 없고 floor0.001의 1:1 매칭으로도 같은 수가 회수된다. 모두 선택 threshold 미만이며 SoC score 약0.003은 확인했다. 정확도 개선을 보장하지 않고 test로 threshold를 조정하지 않는다. |
| Pi FP 24/36, 일반 FP 119/252가 제외 객체와 중첩 | 분모 확인, 중첩 정의 보완 필요 | frozen confidence에서 FP36/252는 재현됐다. 제외 bbox와 **IoU≥0.5면 21/36·98/252**, 교차/예측면적≥0.5면 24/36·116/252다. 원문은 중첩 규칙을 제시하지 않았고 119/252는 재현되지 않았다. 일부 정의에서의24/36을 전체 주장 확인으로 승격하지 않는다. |
| GPIO 환산·절반해상도·D455 하한 | 정정 | Top과 Bottom의 원본 배율이 다르다. fx=640도 실측이 아니다. 축소 결과는 카메라 성능의 하한이 아닌 합성 민감도 시험으로 기록한다. |
| seg는 IC·커넥터만 하도록 목표를 축소 | 보류 | 판독 가능한 IC·커넥터부터 mask 파일럿을 시작할 수는 있다. 그러나 4종 목표를 명목 픽셀 계산만으로 영구 축소하지 않는다. R/C 가독성과 경계 재현성을 실제 촬영에서 확인한다. |

## 2. R04에서 이미 준비·검증한 것

새 원본 사진이나 사람이 만든 mask를 추가한 작업이 아니다. 같은 공개 원본을 새 train/val 그룹으로 나누고 학습 view를 재구성했다. 원본 47장과 target4 bbox 5,896개, 일반/Pi 시험 정답은 보존했다.

| 분할 | 원본 사진 | 보드 그룹 | 원본 bbox | R / C / IC / connector |
|---|---:|---:|---:|---|
| train | 25 | 17 | 3,307 | 1,201 / 1,584 / 204 / 318 |
| val | 9 | 6 | 1,052 | 410 / 454 / 73 / 115 |
| 일반 개발 holdout | 11 | 5 | 1,348 | 443 / 636 / 93 / 176 |
| Pi 개발 holdout | 2 | 1 | 189 | 57 / 104 / 16 / 12 |

val은 기존 train+val의 클래스×원본 크기 분포와 그룹 보존을 기준으로 결정했다. 6그룹 조합 100,947개를 독립 재계산했으며 고정된 결과와 일치했다. 일반/Pi test의 통계·예측을 분할 최적화 입력으로 사용하지 않는다. 새 val에는 R03에서 학습한 그룹이 포함될 수 있으므로 두 팔 모두 **같은 공식 yolo11s.pt**에서 시작한다. R03 학습 가중치에서 이어 학습하지 않는다.

| 학습 자료 | 기준 팔 baseline | 개선 팔 improved |
|---|---:|---:|
| 학습 view | 418 | 968 |
| 구성 | native1024 418 | native1024 418 + context2048 126 + 객체 중심 424 |
| 원본 train 객체 | 3,307 | 3,307 |
| 적어도 한 view에 완전히 포함된 객체 | 3,215 | 3,307 |
| 저장된 라벨 반복 노출 합계 | 6,575 | 24,807 |
| R / C / IC / connector 노출 | 2,186 / 3,054 / 507 / 828 | 9,523 / 11,092 / 1,721 / 2,471 |
| ignore 영역 반복 노출 | 0 | 조각 2,722 + unknown 1,399 |
| 신규 사람 라벨 / 신규 instance mask | 0 / 0 | 0 / 0 |

24,807개는 새로운 독립 부품 수가 아니다. crop마다 같은 부품이 반복된 **저장 라벨 노출**이며, 448회 복원 추출로 실제 학습에서 본 횟수와도 다르다. 실제 노출은 학습 실행 기록에서 집계한다.

두 팔 모두 17개 그룹의 sampling weight 합계를 각각 1로 맞춘다. 그룹 안에서는 IC 또는 connector 정답이 있는 view에 1.5, 나머지에 1.0을 주고 그룹 합으로 정규화한다. 클래스 loss multiplier는 모두 1.0이다. 이 정책은 그룹 선택 확률을 맞추며, 클래스나 고유 부품의 gradient 기여도를 같게 만드는 규칙은 아니다.

데이터 독립 감사 36개 검사를 통과했다. 1,386개 view의 실제 JPEG 바이트를 원본 crop부터 재생성해 SHA를 확인했고, 라벨 좌표 왕복 최대 오차는 4.162e-7 px였다. 원본 그룹·정확한 이미지 SHA의 split 간 중복은 없었다. 물리적으로 같은 보드의 다른 인터넷 사진까지 없다고 증명한 것은 아니다.

감사에서 발견한 native_manifest 상위 집계의 옛 수치는 학습 전에 수정했고 protocol SHA를 갱신했다. 이미지·정답·분할은 이 수정에서 바뀌지 않았다.

## 3. 고정한 학습·선택·평가 규칙

아래는 R04 실행 계약이다. 현재 성능 결과나 학습 완료를 뜻하지 않는다. 실제 epoch·호출 수·중단 여부는 이후 실행 기록으로 확정한다.

| 항목 | R04 고정 규칙 |
|---|---|
| 비교 모델 | 같은 YOLO11s 구조·같은 공식 초기 가중치 SHA를 쓰는 baseline/improved |
| 예산 | 각 팔 최대 20에폭, optimizer 직접 호출 최대 1,165회, 에폭당 448회 복원 추출 |
| 입력·수치 형식 | imgsz 1024, batch 4, nbs 8, FP32(AMP 끔) |
| optimizer | AdamW, lr0 0.001, lrf 0.01, warmup 2에폭 |
| 공통 증강 | LetterBox, HSV, 좌우·상하 반전. mosaic·mixup·무작위 perspective/scale/translation/crop 및 90° 회전은 이번 비교에서 적용하지 않음 |
| 실제 갱신 기록 | optimizer post-step hook, 파라미터별 min/max step, EMA updates, 처리 배치, 클래스·view·그룹별 실제 추출 노출을 분리 기록 |
| 체크포인트 후보 | 완료한 2,4,…,20에폭 후보. 예산으로 조기 종료되면 실제 만들어진 후보·마지막 체크포인트 상태를 기록 |
| 추론 후보 | native: 원본 1024 crop / dual: 원본 1024+2048 crop, 입력 1024 및 원본 좌표 병합 |
| 선택 | val AP50–95 max300 → max100 → offline p50 지연 → 후보 ID 순 |
| 운용 threshold | val의 IoU 0.5 micro-F1, confidence 0.05~0.95(0.05 간격), 동률이면 더 높은 confidence |
| 시험 | 두 팔의 모든 val 비교 종료 → checkpoint·방식·threshold SHA 동결 → 각 선택 팔의 일반/Pi 개발 holdout 평가 |
| 지표 | AP50/AP50–95 max300·max100, 클래스별 P/R/PR, 원본 크기×클래스, 고정 threshold 오류 수, 그룹 단위 recall 구간(가능한 경우) |

기준 팔과 개선 팔 모두 새 split·sampling·batch·증강을 공유하므로, 둘의 차이는 문맥/중심 view와 ignore를 합친 개선 묶음이다. 각 요소의 단독 원인 효과로 해석하지 않는다. R03와 R04의 수치 차이는 split 등 공통 조건까지 달라져 **순수한 모델 개선율**이라고 부를 수 없다.

기존 저장 예측을 새 평가 코드로 CPU 재집계한 AP100/AP300은 R03와 일치했다. 이는 계산 호환성 검사이며 R04 모델 성능 검증은 아니다.

## 4. R03의 기준 성능과 공개 Pi 2장의 한계

| R03 s 모델 | AP50–95 max100 | AP50–95 max300 | 고정 confidence | 재현율 |
|---|---:|---:|---:|---:|
| 일반 시험 11장 / 1,348개 | 20.6953% | 23.3111% | 0.35 | 56.0831% |
| Pi3B 앞·뒤 2장 / 189개 | 23.1528% | 23.1604% | 0.35 | 49.2063% |

Pi의 TP/FP/FN은 R 39/15/18, C 51/13/53, IC 3/3/13, connector 0/5/12였다. 이 2장은 같은 설계의 한 보드 그룹에 해당하며 실물 일련번호·촬영 세션은 확인되지 않았다. 실물 보드 두 개로 계산하지 않는다. 제공된 unknown 67개가 있어 전체 BOM이나 모든 부품을 완전하게 평가한 것도 아니다. 한 그룹에서 보드 일반화 신뢰구간을 만들지 않는다.

두 장을 이미 보며 오류 분석과 개선 방향을 정했으므로 앞으로의 결과는 개발용 holdout이다. 처음 보는 D455 최종 시험을 대체하지 않는다. R03 일반 시험의 12.83–65.50% 구간은 고정 threshold **recall**의 그룹 bootstrap 구간이며 AP 구간이 아니다.

## 5. D455에 맞춰 확인할 사항

제조사 [D455 사양](https://www.realsenseai.com/products/real-sense-depth-camera-d455f/)은 RGB 1280×800/30 fps, 명목 수평 화각 90°, 최대 depth 해상도에서 Min-Z 약 52 cm를 기재한다. Min-Z는 깊이 측정 조건이며 RGB의 최소 초점 거리와 동일하지 않다. RGB 가까운 촬영과 depth 측정 가능성을 따로 확인해야 한다.

명목 화각을 이용한 fx≈640은 실제 SDK에서 읽은 intrinsics가 아니다. 따라서 200 mm에서 3.2 px/mm, 300 mm에서 약 2.13 px/mm라는 계산은 촬영 위험을 예상하는 가정이다. 실물 거리·보드와 같은 평면의 자·원본 fx/fy로 검증해야 한다. 원본 2px 부품을 4배 확대해도 사라진 실제 윤곽이 복원되지는 않는다.

[공식 Pi 3B 축약 회로도](https://datasheets.raspberrypi.com/rpi3/raspberry-pi-3-b-reduced-schematics.pdf)의 J8은 40핀 0.1인치 피치다. 첫 핀~끝 핀 중심 19간격(48.26mm)과 사진의 핀 위치로 추정하면 Top 약22.6px/mm, Bottom 약14.2px/mm로 배율이 다르다. Top의 50.8mm=1,142px 가정을 두 사진 모두에 쓰지 않는다. 이 추정 자체도 렌즈·원근·헤더 높이를 보정한 계측값은 아니다.

현재까지 만든 절반 해상도·흐림 시험은 합성 민감도 분석이다. 실제 D455의 광학 MTF, 초점, 노이즈, 반사를 재현하지 않으므로 성능의 상한·하한이라고 부르지 않는다. 카메라가 나쁘다는 이유로 threshold나 모델만 바꾸기 전에 원본에서 클래스와 경계를 실제로 구분할 수 있는지 확인한다.

## 6. 후속 실물 촬영·라벨 계획 — 미수행 예산안

**현재 신규 D455 사진 0장, 신규 검수 instance mask 0개다. 아래 30+200장은 계획량이다.** 카메라 설정 변경과 촬영은 실제 보드 배치 후 별도 실행 단계에서 진행한다. 이미 진단에 사용한 파일럿을 최종 시험셋으로 승격하지 않는다.

### 파일럿: 30장

보유 Pi 한 대를 우선 사용할 수 있다. RGB 초점이 실제로 맞는 범위에서 가까움·중간·멀어짐 3조건, 앞·뒤 2면, 조명·반사·기울기 5조건을 조합해 30장으로 시작한다. 동일 장면의 연속 프레임 30개를 독립 표본으로 세지 않는다. 거리 200/300mm를 고정 권장값으로 사용하지 않는다.

| 항목 | 수행 계획 |
|---|---|
| 원본 저장 | SDK에서 지원 여부를 확인한 RGB 1280×800 PNG. 지원하지 않으면 실제 profile을 기록하고 계획을 수정 |
| 기록 | physical_board_id, design_id, side, session_id, 조명 ID, 실측 거리, fx/fy, 원본 크기, 노출·gain·white balance 실제 metadata, SHA |
| 광학 확인 | 보드와 같은 평면의 mm 자·분해능 차트. 부품 위치별 px 크기, 초점, 금속 반사와 가림 기록 |
| 노출 | 조건 비교 구간에서는 가능하면 노출·white balance를 안정화·고정하고 실제 값을 기록. 이 보고서가 자동으로 카메라를 변경한 것은 아님 |
| bbox 라벨 | 30장에 보이는 4종을 검토. 종류는 사진 색만으로 정하지 않고 refdes·BOM/회로도·실물 확인 근거 기록 |
| mask 파일럿 | 30장 중 거리·면·선명도 조건이 겹치지 않도록 미리 정한 6장에 4종 mask 검토. 식별 불가한 R/C는 추정하지 않고 class/bbox/mask 상태를 분리 |
| 이중 검수 | bbox 6장(20%), mask 파일럿 중 2장을 두 검토자가 독립 확인. 한 명이면 시간차 재검토라고 기록 |
| 파일럿 종료 판단 | 촬영 조건별 class 판독률, mask 작성 가능 비율, 이중 검수 불일치, 객체당 작성 시간과 unresolved 수를 기록한 후 본 수집 범위 결정 |

픽셀 수 8/16은 진단 구간이며 자동 합격선이 아니다. IC·커넥터부터 mask가 가능하면 그 범위를 별도 결과로 보고하고, 저항·커패시터의 목표는 미완료로 유지한다. 기하가 보이지 않으면 디지털 확대나 SAM 예측을 검수된 mask로 바꾸지 않는다.

### 본 수집: 파일럿과 별도 200장

다음은 보유·대여 등으로 실물 6대를 사용할 수 있을 때의 초기 예시다. 6대 구입을 요구하는 계획은 아니며 실제 보유 수량에 맞춰 조정한다. 사진 수보다 **독립 실물과 설계 수**가 평가 범위를 결정한다.

| 구분 | 실물·설계 배정 예시 | 사진 예산 | 허용되는 해석 |
|---|---|---:|---|
| train | 실물 3대, 사용 가능한 Pi 설계 1~2종 | 120(대당40) | 학습·증강·라벨 보완 |
| val | train과 다른 실물 1대, 가능하면 학습한 설계 | 40 | threshold·체크포인트·입력 방식 선택 |
| test-A | train/val과 다른 실물 1대, 학습에 있던 설계 | 20 | 새 실물의 같은 설계 평가 |
| test-B | train/val에 전혀 없는 설계의 실물 1대 | 20 | 새 설계 평가. 해당 설계 사진은 모두 test-B로 묶음 |
| 합계 | 계획 예시 6대. 실제 식별·확보 전 | 200 | test-A/B를 각각 보고하며 한 그룹 결과를 넓게 일반화하지 않음 |

3대만 있으면 split마다 다른 실물 1대를 배정할 수 있지만 여전히 그룹 수가 매우 적다. 한 대뿐이면 촬영 날짜·재배치 세션을 train/val/test로 나누고 결과명을 **같은 실물의 미관측 세션 평가**로 제한한다. 같은 보드를 여러 면·여러 crop·여러 세션으로 찍어도 실물 ID를 바꾸지 않는다. 새 설계 시험을 주장하려면 그 설계의 다른 실물과 인터넷 사진도 학습/검증에서 제외했는지 확인한다.

### 라벨 수와 가중치 기록 방식

200장은 이미지 예산이며 라벨 개수 보장이 아니다. 각 이미지에서 평가 범위에 속하는 목표 부품을 빠짐없이 확인한다. 예를 들어 확인 가능한 목표가 평균 120개라면 200장에 영상 annotation 약24,000개가 생기지만, 이는 작업량 예시일 뿐 실제 확보량이 아니다. 동일 부품이 20장에 보이면 영상 annotation 20개와 고유 물리 부품 1개를 분리해서 센다.

| 반드시 기록할 수 | 의미 |
|---|---|
| class별 원본 영상 bbox·mask 수 | 실제 검수 완료분만 집계. bbox를 채운 사각형은 mask 정답으로 계산하지 않음 |
| 고유 physical_board_id / design_id / session_id 수 | 이미지 장수와 독립성 분리 |
| 고유 physical_component_id 수 | board_id+면+refdes 등으로 동일 부품의 반복 촬영 구분 |
| connector subtype·IC package 분포 | USB-A, HDMI, RJ45, FFC, microSD, pin header 등 종류 편중 확인 |
| DNP·unknown·가림·truncated·mask 불가 수 | 실패와 제외를 숨기지 않음 |
| 원본 라벨 → crop 노출 → 실제 sampler 노출 | 새 정답과 반복 노출을 구분 |
| 초기 checkpoint SHA·class loss multiplier·group/view weight | 샘플링 우선순위와 손실 가중치를 구분 |
| 작성·검수 시간 | 파일럿 실측 중앙값으로 본 수집 노동량 추정 |

R03에서 제안한 다양성 점검의 시작 목표는 고유 R/C 각300개, IC/connector 각100개다. 보유 보드에서 이를 충족하지 못하면 실제 수와 부족한 subtype을 기록한다. 같은 부품의 중복 촬영으로 이 목표를 충족했다고 계산하거나, 이 숫자만으로 성능을 보장하지 않는다.

미실장 footprint는 새 계약에서 `population_status=unpopulated`와 근거를 기록한다. 원래 source가 connector라고 한 자료를 일괄 삭제하지 않는다. 사람이 식별하지 못한 영역은 `unresolved`로 보존하고, 평가에서 제외한다면 영역 범위·제외된 정답과 예측·평가 가능 면적/객체 비율을 명시한다. 라벨을 비우거나 COCO에 ignore 키만 넣는 방식으로 ignore가 작동했다고 가정하지 않는다.

### 실제 세그멘테이션과 최종 평가

현재 R04는 bbox 검출 실험이다. 보드 외곽 mask, source3 semantic mask, target4의 개별 부품 instance mask를 서로 바꾸어 세지 않는다. 실제 target4 mask가 확보되면 별도 segmentation manifest와 train/val/test 버전을 만들고 mask AP를 계산한다. 미래 데이터에 대한 에폭·가중치·oversampling도 검증 전에 별도 동결한다.

최종 D455 시험에서는 입력부터 결과까지 500프레임 지연을 측정하는 계획을 추가할 수 있다. p50/p95, 처리율, 프레임 누락, 해상도, batch, 장치, 전처리·전송 포함 범위를 기록한다. 500프레임은 시간 측정 표본이며 독립 보드 500개나 정답이 있는 시험 이미지 500장을 뜻하지 않는다. 30fps를 달성했다고 미리 가정하지 않는다.
