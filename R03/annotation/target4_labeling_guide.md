# PCB target4 라벨링·D455 수집 가이드 초안 v1

작성일: 2026-09-28. 목적: 저항·커패시터·IC·커넥터의 종류, bbox, 개별 부품 mask를 일관되게 기록한다. **이 문서는 앞으로 수집·라벨링할 기준안이다. 현재 새로 확보한 D455 target4 사람 mask는 0개다.** 공개 데이터의 기존 정답을 새 D455 사람 라벨로 계산하지 않는다.

## 현재 실제 자료와 계획을 구분한다

| 항목 | 현재 실제 확보·검증 범위 | 계획에만 있는 항목 |
|---|---|---|
| WACV 부품 target4 | 원본47사진, 이름기준29보드그룹, 사람 bbox5,896개. Pi3B 두 면189개는 fine-tuning에서 제외 | target4 mask 없음. bbox를 채운 사각형을 mask 정답으로 쓰지 않음 |
| PCBVision source3 | 공개 RGB53장, IC·전해 커패시터·커넥터 semantic 정답과 R02 파일럿 | 저항·물리 instance ID 없음. connected region을 target4 instance 정답으로 승격하지 않음 |
| D455 target4 | 이번 작업에서 새 실물 촬영·사람 mask 검증 수: 사진0 / mask0 | 아래30장 촬영 파일럿, 이후 조건부200장 수집·라벨링 |
| 다른 Raspberry Pi 공개 보드 자료 | 보드 전체 bbox 또는 보드 전체 polygon 과제 | 보드 전체 mask를 보드 위 부품 mask로 계산하지 않음 |

원본은 `physical_board_id`, `board_design_id`, 보드 면, `capture_session_id`가 있어야 한다. 기존 공개 파일의 물리 개체·세션을 알 수 없으면 `unknown`으로 남긴다. 파일 수·같은 부품의 여러 시야·고유 물리 부품 수를 서로 다른 숫자로 기록한다.

## 클래스 ID와 판단 근거

새 계약 이름: `pcb_component_instance_v1`. 고정 순서는 `0 resistor`, `1 capacitor`, `2 ic`, `3 connector`다. 기존 `smd_v1`와 ID 의미가 다르므로 두 체계를 섞지 않는다.

| 클래스 | 포함 범위 | 판단·기록 |
|---|---|---|
| resistor | 확인된 개별 칩 저항, THT 축형 저항 | `mount_type`, `package`, `refdes`를 속성으로 기록. resistor network·jumper·가변저항을 자동 합치지 않음 |
| capacitor | 확인된 MLCC·전해·탄탈 등 개별 커패시터 | `subtype`으로 MLCC/electrolytic/tantalum/unknown을 구분. 전해만 제공하는 source와 범용 capacitor를 구별 |
| ic | 확인된 집적회로. 기능을 확인할 수 있는 전압조정기 등도 포함 가능 | DIP/SOIC/QFN/BGA/DPAK 등의 패키지는 별도 속성. 단자 수나 모양만으로 transistor를 IC로 바꾸지 않음 |
| connector | PCB에 장착된 커넥터 어셈블리 한 개 | USB·HDMI·전원잭·핀헤더 등 `subtype` 기록. 접점 하나씩을 별개 부품으로 세지 않음 |

가능한 판단 근거는 회로도/BOM·명확한 표기·검토자의 부품 확인 순으로 기록한다. 저항은 검정, 커패시터는 갈색이라는 색 단서 하나만으로 정답을 만들지 않는다. 부품 종류는 알지만 패키지는 모르면 class는 유지하고 `package=unknown`으로 둔다. class 자체가 불명확하면 `review_status=unresolved`로 남긴다.

## mask 경계: 보이는 몸체와 확인 가능한 일체형 단자

기본 경계 프로필은 `visible_package_and_terminals_v1`이다. 실제 보이는 부품 몸체와 부품 자체의 금속 단자/리드가 경계 대상이다. 아래 규칙을 파일럿에서 동일하게 적용한다. 기존 source bbox가 동일한 경계 프로필이라는 가정은 하지 않는다.

| 대상 | 포함 | 제외 |
|---|---|---|
| 칩 R·MLCC | 몸체와 부품 양끝 금속 단자 | PCB 패드, 솔더 필렛, 실크, 그림자 |
| 걸윙 IC·DIP 등 | 몸체와 눈으로 구별되는 부품 리드의 실제 보이는 영역 | 리드 사이 배경, PCB 패드·솔더. 리드 끝들을 연결한 가상의 큰 다각형을 만들지 않음 |
| QFN·BGA | 보이는 몸체 외곽, 실제 보이는 부품 단자만 | 몸체 아래 보이지 않는 단자나 볼을 추정하여 추가하지 않음 |
| THT 축형 저항 | 몸체. 몸체 밖 긴 와이어는 이 초안에서 제외 | 보드와 겹친 가는 와이어·패드·솔더. `boundary_profile=tht_resistor_body_v1` 별도 기록 |
| 전해 커패시터 | 위에서 보이는 캔/몸체 | 아래 가려진 리드, 그림자, 반사광 번짐 |
| 커넥터 | 한 어셈블리의 하우징과 붙어 있는 금속 쉘. 확인되는 접점은 같은 instance | 케이블, 분리된 플러그, PCB 패드·솔더. 보드 위에 드리운 그림자 |

반사로 하얗게 보이더라도 부품 내부로 확인되면 포함한다. 번진 빛이 경계 밖으로 퍼진 부분은 제외한다. 실제 틈으로 PCB/배경이 보이면 배경으로 남기고, 어두운 커넥터 내부를 자동으로 구멍으로 뚫지는 않는다. 열린 틈과 실제 부품 내부를 구별할 수 없으면 검토 대상으로 표시한다.

가려진 부품은 **보이는 영역만** 그린다. 가림 뒤 윤곽을 상상해서 복원하지 않는다. 한 부품의 보이는 영역이 여러 조각이면 같은 instance ID의 multipart mask로 보존한다. 원본 정답은 instance raster/RLE 또는 multipart polygon을 보존하는 형식으로 관리한다. 학습 형식이 한 개 단순 polygon만 지원한다면 변환 손실을 검사하며, 떨어진 조각을 가짜 선으로 이어 원본 정답을 바꾸지 않는다. 필요하면 변환 가능한 샘플만 별도 학습 view로 만들고 제외 수·이유를 기록한다.

이미지 경계에 잘린 부품은 보이는 부분만, `truncated=true`로 기록한다. 인접 부품은 각각 별개의 instance다. 닿아 보인다는 이유로 합치지 않는다. bbox는 확정된 mask의 원본 좌표 min/max에서 계산하되, 기존 bbox-only source는 독립 라벨로 유지한다.

리드나 몸체 경계를 분간할 수 없는 작은 부품은 확대 화면·SAM 출력으로 추측하지 않는다. class/bbox만 확인되고 mask가 불명확한 경우 각각의 상태를 나눈다. 원본 짧은 변 <8 / 8–16 / 16–32 / ≥32px는 품질 검토 구간이지 자동 라벨 삭제 기준이 아니다.

## unknown·비대상·배경을 구별한다

- 다이오드·트랜지스터·인덕터·LED처럼 확인된 비대상은 이름/영역을 부가 annotation으로 보존하며 target4 class를 붙이지 않는다.
- 종류를 모르는 물체는 `unresolved`다. 비대상으로 확인된 배경과 같지 않다. 자동 `other_component` 클래스를 만들지 않는다.
- target4가 하나도 없다고 사람이 확인한 이미지만 target4 negative로 사용할 수 있다. 작아서 확인하지 못한 부품이 있는 사진을 빈 라벨로 처리하지 않는다.
- 모든 목표 부품이 검토되지 않은 이미지는 mask mAP 시험 정답으로 승격하지 않는다. 애매한 부분을 조용히 빼면 정상 예측이 오검출로 계산될 수 있다. 해결하지 못한 사진/영역은 별도 제한 평가로 표시하고 범위·제외 수를 공개한다.
- 현재 WACV Pi3B에는 unknown67개가 있다. 이 자료의 AP는 제공된 target4 annotation 기준이며 전체 부품/BOM 정확도가 아니다.

## 라벨 작업·검수 순서

1. 원본 PNG와 촬영 메타데이터를 잠그고 파일 SHA를 기록한다. 원본을 덮어쓰지 않는다.
2. 보드·설계·세션 그룹을 먼저 정한 뒤 split을 고정한다. 크롭·타일·증강은 그 다음이다.
3. class와 근거를 먼저 확인한 뒤 instance ID, 경계, 가림/잘림, 패키지 속성을 기록한다. 보이는 목표 부품 전체를 빠짐없이 검토한다.
4. Train에서 보조 도구/SAM을 사용했다면 `annotation_method=assisted_then_human_reviewed`로 기록하고 사람이 수정·확정한다. Val/test는 해당 검출 모델의 예측을 정답으로 사용하지 않으며 원본에서 독립적으로 확인한다.
5. 파일럿의 10~20%는 두 명이 별도로 라벨링한다. 크기·클래스별 class 일치도와 mask IoU를 계산하고 불일치를 조정한다. 한 명만 있다면 시간 간격을 둔 재검토임을 적고 두 사람 검수라고 부르지 않는다.
6. polygon/raster 유효성, 원본 범위, instance 중복, bbox 유도, export/import 왕복을 검사한다. train/val/test에 같은 원본·보드 그룹이 섞이지 않는지 확인한다.

사람 간 IoU는 라벨 불확실성을 보여주는 관측값이며 모델 성능의 엄밀한 상한이 아니다. 평가 라벨을 나중에 바꾸면 버전과 이유를 기록하고 이전 결과와 새 결과를 구분한다.

## D455 수집 계획: 먼저30장, 이후 조건부200장

현재 신규 D455 수집량0장과 계획량을 별도 관리한다. 카메라 연결/영상 수신은 이번 문서 작성으로 검증된 것이 아니다.

**파일럿30장:** 실제 사용할 조명과 보드 배치에서 거리·작은 부품의 선명도·원본 픽셀 수를 확인한다. 보유 보드 수를 먼저 실제대로 적고, 최대3개 실물 보드에서 각10장을 시작안으로 삼는다. 한 개만 있다면 같은 보드30장으로 조건을 시험하되 보드 다양성이 확보됐다고 말하지 않는다. 프레임을 연속 저장한 수는 독립 표본 수가 아니다. 이30장으로 경계 규칙·촬영 조건을 정했다면 최종 시험셋에 넣지 않는다.

거리 후보는 실제 RGB 초점이 확인되는 범위에서 가까움/중간/멀어짐으로 정하고 각 값을 실측한다. 특정 근거 없는 근접 거리를 선명하다고 가정하지 않는다. 원본 RGB 크기·fps·intrinsics의 fx/fy, 노출·게인·화이트밸런스, 거리, 조명, 보드 면·기울기, 파일 SHA를 저장한다. GSD≈Z/fx는 정면 평면의 근사이므로 자/알려진 부품 치수로 검증하고 기울어진 보드에는 위치별 원근차를 고려한다. 깊이 정확도와 RGB 작은 부품 가독성은 별도다.

**본 수집200장 예산안:** 현재 보유한 보드 수는 확인되지 않았다. 먼저 보유 보드로 시작하며 25개 보드 구매 같은 조건을 요구하지 않는다. 아래는 작업량 배분 예산이고 실제 그룹 수에 따라 장수는 바뀐다. 다른 실물 일반화를 시험하려면 train/val/test에 서로 다른 실물을 배정할 수 있어야 한다. 3대라면 split당 1대 수준의 매우 작은 시작 시험일 뿐, 충분한 보드 다양성이 확보된 것은 아니다. 한 대라면 아래 세션 평가 방식으로 범위를 제한한다.

| 분할 계획 | 그룹 배정 | 사진 예산 | 용도 |
|---|---|---:|---|
| train | 보유 실물·설계·세션 확인 후 고정 | 약120 | 학습·라벨 수정 |
| val | 선택한 독립성 수준에서 train과 분리 | 약40 | 체크포인트·추론 방식·threshold 선택 |
| test | 같은 기준으로 train/val과 분리 | 약40 | 미리 정한 후보의 최종 평가 |
| 합계 | 실물/설계/세션 수를 각각 실제 기록 | 약200 | 실제 확보량 아님 |

설계 일반화를 주장하려면 같은 설계의 다른 개체까지 같은 split에 묶고 test 설계를 train/val에서 빼야 한다. 단지 다른 시리얼의 같은 Pi 모델을 시험했다면 **다른 실물 개체** 시험이지 **새 설계** 시험은 아니다.

**실물 Pi가 한 대뿐인 경우:** train/val/test를 촬영 세션으로 나눌 수 있으나 결과 명칭은 `같은 실물 보드의 미관측 세션 평가`다. 같은 보드의 사진을 나누어 `미관측 보드 평가`라고 부르지 않는다. 다른 실물 시험과 다른 설계 시험은 자료를 확보할 때까지 미수행으로 둔다.

## 라벨 수·시간 예산을 기록하는 방법

계획의 시작 목표는 고유 물리 부품 기준 저항·커패시터 각300개, IC·커넥터 각100개 수준의 다양성 확인이다. 이는 학습 성능 보장이나 반드시 달성된 수가 아니다. 같은 보드의 같은 부품을8번 촬영하면 고유 물리 부품1개, 영상 annotation8개로 센다. 희소한 커넥터·IC 패키지 다양성이 부족하면 같은 보드 사진을 추가하는 것보다 다른 보드 확보를 우선한다.

파일럿에서 실제 `class별 영상 annotation 수`, `고유 물리 부품 수`, `unresolved 수`, `mask 한 개 작성·검수 시간`을 측정한다. 이후 예상 작업시간은 **예상 annotation 수 × 실측 중앙 작성시간 + 검수시간**으로 계산한다. 아직 측정하지 않은 시간을 실적으로 기록하지 않는다. 모든 목표 부품을 검토해야 하므로 특정 개수만 채우고 같은 이미지의 나머지를 비워두지 않는다.

최소 기록 필드:

```text
image_id, image_sha256, physical_board_id, board_design_id, board_side,
capture_session_id, split, native_width, native_height, fx, fy, distance_mm,
exposure, gain, white_balance, lighting_id,
instance_id, physical_component_id, class_id, class_evidence, refdes,
mount_type, package, subtype, boundary_profile, polygon_or_rle,
occluded, truncated, class_status, bbox_status, mask_status,
annotation_method, annotator_id, reviewer_id, annotation_version
```

모델 비교는 사용자 예산에 맞춰 짧은 smoke와 최대20epoch 파일럿으로 운영하고 실제 optimizer update를 함께 기록한다. 카메라 도메인의 최종 bbox/mask AP는 이 가이드로 확정한 실제 D455 시험 정답을 확보한 뒤에만 보고한다.
