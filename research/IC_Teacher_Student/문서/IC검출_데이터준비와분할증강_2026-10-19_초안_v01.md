# PCB IC 데이터 준비·분할·증강 프로토콜

프로토콜 `pcb-ic-ts-draft-v01`. 아래 수치와 절차는 실행 전 검토할 초안이며, 확보한 데이터 규모나 실험 성과를 나타내지 않는다.

## 1. 데이터 선택과 이용조건

주 과제는 단일 클래스 `IC`의 bounding box 검출이다. PCB 전체, 보드 종류, 저항·커패시터, 구리 패턴 결함을 IC 정답으로 자동 치환하지 않는다. 후보 데이터·공식 출처·확인 수준은 [연구 토픽 문서](IC검출_연구질문과선행연구_2026-10-19_초안_v01.md)에 정리한다.

데이터를 받기 전에 제공자, 원본 URL, 버전/DOI, 다운로드 날짜, 원 라이선스, 이용 목적, 수정·가공·재배포 허용 범위를 로컬 데이터 카드에 기록한다. 원문 약관이 없거나 충돌하면 반입·학습 허용 여부를 미확인으로 두고 해소한 뒤 진행한다. 논문의 공개 여부와 데이터의 이용조건은 별개다. 공개 저장소에는 원본·crop·라벨·실제 manifest·촬영정보를 넣지 않는다.

FICS-PCB와 FPIC 같은 계보가 겹치는 자료는 별도 독립 표본으로 합치지 않는다. 기존 프로젝트의 공개 URL도 신규 재배포 허가로 간주하지 않는다. 이미 평가에 사용한 데이터는 개발 평가로 표시하고 새 봉인 시험셋으로 다시 이름 붙이지 않는다.

## 2. 원본 보존과 라벨 검수

1. 원본은 수정하지 않고 로컬의 읽기 전용 보관 위치에 둔다. 영상 바이트와 annotation 바이트의 SHA256, 출처 ID, 원본 크기와 라벨 변환 버전을 기록한다. 변환 산출물은 원본과 분리한다.
2. PCB 실물 ID, 촬영 session, 동일 원본에서 파생한 view/crop, 중복·근접중복 관계를 확인한다. 같은 실물 또는 같은 원본·세션에서 독립성을 주장할 수 없는 자료는 하나의 연결된 `group_id`로 합친다. 자료 간 같은 기판도 같은 전역 그룹에 넣는다.
3. 정확히 같은 해시의 중복은 대표 원본 하나만 남겨 파생 목록으로 연결한다. 해시가 달라도 같은 PCB의 crop·인접 프레임·회전본이면 그룹을 합친다. 그룹을 모르면 독립성을 추정하지 말고 격리한다.
4. 원 클래스→IC 매핑과 패키지 포함/제외 기준을 문서로 고정한다. polygon을 box로 바꿀 때는 외접 사각형 정의를 고정하고 사람이 검수한다. VOC/COCO의 좌표 기준·끝점 포함 여부를 확인한 뒤 내부 연속 좌표 `xyxy`로 통일한다.
5. 유한 좌표, `0 <= x1 < x2 <= W`, `0 <= y1 < y2 <= H`, 중복 box, 누락 IC, box 밖 잘린 IC를 검사한다. 모호한 부품·잘린 영역·미라벨 후보는 ignore 영역으로 기록하며 background로 강제하지 않는다.
6. **완전한 IC 라벨이 확인된 영상**만 v01 학습에 넣는다. 완전한 음성 영상은 IC가 없음을 확인한 경우에만 포함한다. 미검수·부분 라벨은 격리하고 HN 후보로 사용하지 않는다.

현재 importer, 영상/라벨 내용 검사, 근접중복 판정과 ignore mask 생성기는 미구현이다. 메타데이터 도구가 위 실질 검수를 대신하지 않는다.

## 3. 그룹 분할과 봉인

분할 도구는 아직 분할을 정하지 않은 신규 corpus를 위한 것이다. 기존에 승인·고정한 분할이나 봉인 test가 있으면 도구로 다시 섞지 않고 기존 배정을 보존한다. 해당 자료의 importer와 교집합 검사 절차는 별도로 구현해야 한다.

분할은 crop·resize·증강보다 먼저 수행한다. v01 초안은 **그룹의 SHA256 기반 70/15/15 기대 비율**을 사용한다. 영상 수의 정확한 70/15/15를 보장하지 않으며, 큰 그룹으로 분포가 치우칠 수 있다.

```text
digest = SHA256(UTF8("pcb-ic-ts-v01|" + group_id))
u = int(digest, big_endian) / 2^256
train: u < 0.70
val:   0.70 <= u < 0.85
test:  0.85 <= u
```

실제 도구는 부동소수점 대신 정수 비교를 사용한다. 입력 순서와 무관하게 같은 그룹이 같은 분할로 간다. `group_id`는 비식별 ASCII 식별자로 고정하며 나중에 이름을 바꾸면 분할도 바뀔 수 있다. 평가 점수를 보고 seed나 그룹명을 바꾸지 않는다.

헤더 양식의 필드는 `source_id, group_id, image_id, relative_path, image_sha256, annotation_sha256, label_status, license_id, license_review`다. `relative_path`는 로컬 데이터 루트 아래 POSIX 상대경로만 기록한다. 도구는 `label_status=complete_ic_bbox`, `license_review=local_use_verified`라는 **작성자의 선언**을 확인한다. 선언의 진위나 재배포 권리는 검증하지 않는다.

분할 후 원본 그룹·영상 해시가 분할 간 겹치지 않는지, 크기 구간과 음성 영상이 지원되는지 검사한다. 비어 있는 분할은 실행을 중단한다. 필요한 표본 수는 효과 크기와 그룹 다양성에 따라 사전 결정하고, 부족하면 시험 내용을 보며 재분할하지 말고 데이터 수집 계획을 수정한다. 분할 CSV는 새 경로에 배타적으로 생성하므로 과거 파일을 덮어쓰지 않는다.

test payload는 별도 접근 통제 영역에서 보관하고 모델·손실·변환·evaluator·운영 임계값·평가 대상 모델 목록을 동결한 뒤에만 연다. 새 방법을 시험하기 위해 과거 봉인셋을 임의로 열지 않는다. 한번 열람한 시험을 이용해 방법을 바꾸면 그 시험은 이후 개발 자료이며 새로운 독립 검증이 필요하다.

## 4. 무잡음·열화 입력 쌍

v01은 기하 증강을 최소화해 좌표 대응을 명확히 한다. RGB로 읽고 원본 종횡비를 유지해 `640×640` letterbox canvas를 만든다. 좌상단 padding을 포함한 affine 좌표 변환을 GT와 ignore 영역에 동일하게 적용한다. 축소 시 box가 사라지는 조건과 clipping 규칙도 importer에서 검사한다. flip, crop, mosaic, mixup은 v01에서 끈다.

이 canvas를 `x_c`라 하고, 같은 `x_c`에서 `x_n`을 파생한다. 픽셀은 `float32 RGB [0,1]`이다.

1. scale `s ∈ {1.0, 0.5, 0.25}`로 축소한다. 크기는 각각 `640, 320, 160`이다.
2. 같은 640 canvas로 복원한다. 축소·확대 모두 `torch.nn.functional.interpolate(mode="bilinear", antialias=True, align_corners=False)`를 사용한다. `s=1`은 재보간 없이 복사한다.
3. 독립 Gaussian noise `ε ~ N(0, σ²)`, `σ ∈ {0, 0.02, 0.05}`를 더하고 `[0,1]`로 clip한다. sigma는 8-bit 0~255 단위가 아니다.
4. 입력 크기와 geometry를 같게 유지하므로 두 경로의 GT·ROI는 동일한 canvas 좌표를 쓴다. 저해상도 GT 자체를 임의로 축소된 좌표에 남겨 두지 않는다.

train은 위 3×3 조합을 각 영상 방문마다 균등 표집한다. `(1,0)`도 포함하므로 paired clean 조건의 계산 효과를 분리한다. 조합 선택과 noise는 각각 별도 RNG stream을 사용한다. seed 생성 문자열은 구분자 `|`를 포함한 UTF-8이며 image ID에 `|`를 허용하지 않는다.

```text
train seed = SHA256(seed|epoch|image_id|visit_index|stream)의 앞 8 bytes, big endian
eval seed  = SHA256(eval_seed|image_id|scale|sigma|noise)의 앞 8 bytes, big endian
```

epoch는 0부터 시작하고, `visit_index`는 해당 epoch에서 sampler가 같은 image ID를 뽑은 횟수의 0-based 값이다. DataLoader worker의 실행 순서로 seed를 정하지 않는다. evaluation의 scale/sigma는 JSON의 수를 표준 문자열 `1.0/0.5/0.25`, `0.0/0.02/0.05`로 직렬화한다. stream은 `select`와 `noise`로 구분한다. hash 앞 8 bytes 값으로 CPU `torch.Generator`를 각각 초기화한다. scale 우선, sigma 후순위의 9개 조합 목록에서 `torch.randint(0,9)`로 선택하고, noise stream의 `torch.randn(shape, dtype=float32)`를 사용한다. PyTorch 버전과 golden output 해시는 구현 시 동결해야 한다. **현재 augmentation 코드는 없으며 바이트 단위 재현성을 검증하지 않았다.**

## 5. 평가용 변환

원본 test 그룹을 새로 복제하지 않고, 동일 영상에 clean과 3×3 grid를 결정적으로 적용해 짝지어 평가한다. clean `(1,0)`을 중복 집계하지 않는다. 주 강건성 평균은 clean을 제외한 8조건의 AP 산술평균이며, 조건별 AP와 가장 나쁜 조건도 함께 보인다. clean 저하와 noise-only/low-resolution-only/combined를 따로 보고한다.

JPEG, blur, 실제 조명·거리·D455 촬영 조건은 v01에서 평가하지 않는다. 향후 확장 시 개발 검증으로 별도 사전등록하며, 합성 Gaussian·축소영상의 결과를 물리 카메라 검증으로 표현하지 않는다.
